## the setup

WebVoyager is 643 live-web tasks across 15 real sites — booking flights, finding papers on arXiv, comparing products. no sandboxes, no mocks. a task passes only if the final answer is verifiably correct.

we ran the full suite, pass@1, against the strongest publicly available computer-use models. same tasks, same day, same network conditions. every run is recorded — video, HAR, and agent trace — and the harness is open source.

## why small models win here

navigating the web is not a general-reasoning problem. it's thousands of small, latency-sensitive decisions: which element to click, when a page has settled, whether a login succeeded. a 7B model specialized on web interaction makes those calls faster and more consistently than a frontier model prompted to do the same — and it never gets creative about clicking the wrong button.

we keep a larger model in the loop only where it earns its cost: task planning and recovery from genuinely ambiguous states. everything else — grounding, waiting, verification — runs on small specialized models co-located with the browser. round-trips die; reliability compounds.

```python
from smooth import SmoothClient

client = SmoothClient()
with client.session() as session:
    task = session.run_task("book the 7:05am nyc → la flight")
    # pass@1: this either works or you see exactly why in the trace
```

## what actually moved the number

in descending order of impact:

- **action verification.** every action is checked against the resulting DOM state before the agent proceeds. wrong-click recovery went from "hope" to a code path.
- **smart waiting.** most failures on live sites are timing failures. we model page-settle explicitly instead of sleeping.
- **structured grounding.** the agent sees an annotated accessibility tree plus pixels, not pixels alone. small models ground far better on structure.
- **stealth.** you can't pass a task if you're stuck on a captcha. our chromium fork gets challenged less to begin with.

## caveats, because benchmarks lie by omission

WebVoyager sites change; numbers drift a few tenths between runs. we report the median of three full runs and publish every disagreement. pass@1 also hides cost and latency — smooth completes the suite 5x faster and at roughly a tenth of the inference spend, which for production workloads matters more than the last percentage point.
